# ブラウザミニゲームの作成(HTML5/Canvas)

**URLひとつでLINEに共有でき、インストール不要でスマホからすぐ遊べる**のが最大の利点。
反射神経系・パズル・クイズ・スコアアタックなど、1プレイ30秒〜2分の小さいゲームに向く。
リッチな3Dや本格マルチプレイならRoblox(`roblox-game-dev` Skill)を検討する。

## 最初に決めること(ユーザーに確認)

1. **コアループ**: 何をしたらスコアが増えて、何をしたら終わるか(1文で)
2. **操作**: スマホの**タップ/スワイプだけで成立するか**(閲覧の大半はLINEから開くスマホ。
   キーボード前提の企画はこの時点で作り変える)
3. **1プレイの長さ**: 30秒〜2分に収める(LINEの合間に遊ぶ想定)
4. **競う要素**: 自己ベスト(localStorage)で足りるか、仲間とのランキング共有が要るか
   (ランキング共有はサーバーが必要 → `new-shared-webapp` Skillの構成に切り替え)

## 構成(静的サイト・ライブラリなし)

```
game/
├── index.html   # タイトル・Canvas・リトライボタン
├── game.js      # ゲーム本体
├── style.css
└── images/      # ogp.jpg など (絵文字・図形描画だけなら画像なしでも可)
```

`new-website` Skillの基本(viewport・OGP・軽量化)はゲームでも全部適用する。
OGP画像をゲーム画面風にするとLINEで共有したとき遊んでもらいやすい。

## 実装の骨格(必ず入れるもの)

1. **状態機械**: `title → playing → gameover` の3状態を明示的に持ち、
   描画と入力処理を状態で分岐する(リトライは gameover → playing)
2. **ゲームループ**: `requestAnimationFrame` で `update(dt)` と `draw()` を分離。
   **経過時間(dt)ベース**で動かす(端末の性能差・省電力モードでも速度が変わらない)
3. **入力はタッチ最優先**: `pointerdown`/`pointermove` で実装するとタッチとマウスを
   1つのハンドラで扱える。Canvasに `touch-action: none` を指定し、
   スワイプでページがスクロール/引っ張り更新しないようにする
4. **Canvasのサイズ**: 画面幅にフィットさせ、`devicePixelRatio` を掛けた実ピクセルで
   描画してぼやけを防ぐ(リサイズ・画面回転にも追従)
5. **ハイスコア**: `localStorage` に保存し、タイトルとゲームオーバー画面に表示
6. **効果音(任意)**: WebAudio。**最初のタップで** `AudioContext.resume()` する
   (ユーザー操作前は再生できない)。音が無くても遊べるようにする

## テスト

1. `python3 -m http.server 8000` で起動し、Playwrightでスマホサイズ(375x812)で実際に
   プレイ操作(タップ)して動作確認+スクリーンショット
   (リモート環境のChromiumは `/opt/pw-browsers/chromium`、`playwright install` 不要)
2. チェック項目: タイトル→プレイ→ゲームオーバー→リトライが一巡する /
   スコアとハイスコアが正しい / 連打・同時タッチで壊れない /
   画面回転しても崩れない / 60秒放置でエラーが出ない(コンソール確認)
3. 仕上げに実機(LINEのトーク内ブラウザ)で操作感を確認してもらう

## 公開とURL共有

- `website-publish` Skill(GitHub Pages)で公開し、`website-quality-check` を一巡
- グループLINEへはノート投稿+アナウンス。「◯秒で遊べる+ハイスコア報告してね」の
  一言を添えると遊ばれやすい
