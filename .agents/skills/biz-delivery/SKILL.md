# 納品の手順(プレビュー → 入金 → 本納品)

**「透かし入りプレビューで確認 → 入金 → 透かしなしを納品」**の順を守る。
先に完成版を送ると支払いが滞りやすい。各ステップで台帳(`biz-order-ledger`)を更新する。

## 共通フロー

1. **制作完了** → 品質チェック(動画=`qc.py` ALL PASS / デザイン=`apparel-graphic-design`
   のチェック / Web=`website-quality-check`)
2. **透かし入りプレビューを送付** → ステータス「確認待ち」
3. **OKをもらったら入金案内**(`biz-customer-messages` の文面)→「入金待ち」
4. **入金確認後、完成版を納品** →「完了」。お礼メッセージも送る

## サービス別の納品物

### ギフト動画

- プレビュー(透かし入り):

  ```bash
  cd gift-video
  python scripts/watermark.py orders/<ID>/output/<ID>_portrait_1080x1920.mp4 --out preview.mp4
  ```

- 本納品: 縦型・横型の2ファイル(`output/` の透かしなし元ファイル)
- **LINEで送る場合の注意**: 動画は自動再圧縮されて画質が落ちる+サイズ上限がある。
  長い/高画質のものはGoogle Drive等のリンク納品が確実。LINE直送用に軽くするには:

  ```bash
  ffmpeg -i in.mp4 -vf scale=-2:720 -c:v libx264 -crf 26 -c:a aac -movflags +faststart out_light.mp4
  ```

### アパレルデザイン

- プレビュー: 生地色に重ねた確認用画像(`rasterize.py --background`)。原寸PNGはまだ渡さない
- 本納品: 入稿用300dpi透過PNG+元SVG+「実寸幅◯cm・色数◯色」のメモ
  (入稿先の業者に直接送る場合は業者の指定形式に合わせる)

### Webサイト/アプリ

- プレビュー: 公開前URL(Renderのプレビュー環境)またはスクリーンショット一式
- 本納品: 本公開+お客様側で必要な管理情報の引き継ぎ
  (**自分のアカウントを渡さない**。お客様のGitHub/Render/LINEアカウントで作り直すか、
  運用込みで請け負うかを最初に決めておく)
- 保守(修正・更新)を続けるかどうかと料金を納品時に明確にする

## 納品後

- 台帳を「完了」に更新し、メモに納品日を記録
- 制作データは消さずに保管(リポジトリ内 or 注文フォルダ)。リピート・修正依頼が来る
- よい作品はポートフォリオ掲載の許可をお客様にもらう(`new-website` Skillで
  ポートフォリオページを作れる)
