# 家計簿アプリ(SCB Connect通知連携)

銀行(SCB)のLINE通知から自動で記帳し、現金の買い物は手で足す個人用の家計簿。
スマホのブラウザで使う。使うのは本人1人だけなので、URL + 合言葉で入る。

設計の背景と全体計画は [`../docs/kakeibo-app-plan.md`](../docs/kakeibo-app-plan.md)。

## できること

- **銀行通知の取り込み** — SCB Connect の通知をスクショして選ぶだけ。
  金額・日時・**相手口座(名前・口座番号・銀行)**・残高を自動で読み取る
- **カテゴリの自動入力** — 「この相手はこのカテゴリ」を直すたびに覚える(学習辞書)。
  次から同じ相手は自動で入る
- **現金の手動入力** — 金額 → カテゴリの大ボタン → 登録の2タップ
- **残高照合** — 通知に載っている残高が前後で繋がっているかを自動チェック。
  ズレていれば「取り込み漏れ」として警告し、1タップで `Adjust` として記録できる
  (これまでスプレッドシートのAdjust列で手作業していたもの)
- **月次集計とCSV** — 収入・支出・差引とカテゴリ別内訳。CSVは
  これまでのスプレッドシートと同じ「日付 × カテゴリ列」の形式

## 画面

| タブ | 内容 |
|---|---|
| 入力 | 現金クイック入力 / 通知スクショ・テキストの取り込み / 残高ズレの警告 |
| 履歴 | 月別の一覧。タップで編集・削除 |
| 集計 | 月の収入・支出・差引、カテゴリ別、CSVダウンロード |

ヘッダーの ⚙ から**自分の口座**(例: `X-4211`)を登録する。
通知の「จากบัญชี / เข้าบัญชี」のうち、登録した口座でない側を相手として記録する。
未登録でも入出金の向きから相手を判定できるが、登録しておくほうが確実。

## ローカルでの起動

```bash
npm install
rm -rf kakeibo/data
APP_PASSCODE=test123 PORT=3100 npm run kakeibo
# → http://localhost:3100
```

`GEMINI_API_KEY` を設定しない場合、スクショ取り込みだけが無効になる
(手動入力と「テキストを貼り付けて取り込む」は使える)。

テスト:

```bash
npm run test:kakeibo   # 通知の解析・残高照合・集計(実際の通知サンプルを使用)
```

## 環境変数

| 変数 | 必須 | 説明 |
|---|---|---|
| `APP_PASSCODE` | ✅ | ログイン用の合言葉。未設定だとログインできない |
| `SESSION_SECRET` | ✅ | セッショントークンの署名鍵(Renderの `generateValue` で自動生成) |
| `DATABASE_URL` | 本番✅ | PostgreSQL(Supabase)。未設定だとローカルJSON保存になり、再デプロイで消える |
| `GEMINI_API_KEY` |  | 通知スクショの解析に使う。未設定ならスクショ取り込みのみ無効 |
| `GEMINI_MODEL` |  | 解析に使うモデル(既定 `gemini-2.0-flash`) |
| `APP_TITLE` |  | アプリのタイトル(既定「家計簿」) |
| `ALLOW_INSECURE_DEV` |  | `1` で合言葉なしログイン。**開発専用。本番では絶対に設定しない** |

`.env.example` / `render.yaml` にも同じ変数を載せてある(増やしたら3点セットで更新する)。

## 公開(Render + Supabase)

`render.yaml` に `kakeibo-app` サービスとして定義済み。注文アプリと同じリポジトリだが
**別サービス・別データベース**として動く。手順は注文アプリの `../SETUP.md` の
Supabase / Render の項と同じで、違いは次の3点:

1. Start Command は `npm run kakeibo`
2. LINEログインは使わないので LIFF まわりの設定は不要
3. 環境変数は上の表のとおり(`APP_PASSCODE` は必ず設定する)

公開後、スマホのブラウザでURLを開き「ホーム画面に追加」しておくとアプリのように使える。

## 構成

| ファイル | 役割 |
|---|---|
| `server.js` | API(認証・取引CRUD・取り込み・集計・残高照合・SSE) |
| `lib/auth.js` | 合言葉の照合とHMAC署名セッション(12時間)+総当たり対策 |
| `lib/store.js` | 保存層。PostgreSQL / ローカルJSONの二重構造+起動時マイグレーション |
| `lib/scb.js` | **SCB通知の解析**。テキストもスクショも最後はここの `buildDraft` を通る |
| `lib/vision.js` | スクショ → 通知カードの生文字列(モデルには転記だけをさせる) |
| `lib/ledger.js` | 集計・残高照合・月範囲(タイ時間) |
| `shared/constants.js` | カテゴリ・上限値・銀行名。サーバー/ブラウザ共用(UMD) |
| `public/` | フロントエンド(素のHTML/CSS/JS) |
| `test/` | 通知解析と残高照合のテスト(`node --test`) |

### 通知の解析について

モデル(Gemini)には**カードに書かれている文字列をそのまま返すこと**だけをさせ、
入出金の判定・相手口座の特定・日時や金額の正規化は `lib/scb.js` の決まった処理で行う。
モデルを差し替えても家計簿側のロジックは変わらないし、テキスト貼り付けと同じ経路を通る。

日時はタイ時間(UTC+7)で解釈する。仏暦(2569年など)で来た場合は西暦に直す。
